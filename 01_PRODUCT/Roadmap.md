# Roadmap 2026–2027

下列為規劃目標，非已承諾日期。每季依資料重新評估。

| 時間 | 目標 |
|---|---|
| 2026 Q4 | Foundation：PRD、UX、技術架構、MVP |
| 2027 Q1 | Beta：預約、申請、取消改期、基本 CRM |
| 2027 Q2 | Business V1：套票、固定週期、行事曆 |
| 2027 Q2 | Growth：候補、來源追蹤、續購 |
| 2027 Q3 | Creator & Studio：多地點、團課、多人 |
| 2027 Q3 | 區域 LINE／WhatsApp／金流試驗 |
| 2027 Q4 | Connect Beta：跨供給方排程與配對 |
| 2027 Q4 | Marketplace 研究 |
| 2028+ | 供需密度足夠時再推出 Discover |

Q1 決策門檻：真實使用。Q2：留存與付費。Q3：可重複獲客。Q4：跨供給方需求及配對價值。

團課在服務模式表稱 V1.5、需求列 P2；實際優先級及排程由需求證據與容量決定。


## 2026-10-20 新增：關心、回約與自然語言入口

詳細需求：[產品補充 v1.1](Client_Care_and_Action_Assistant_PRD.md)。下列是依證據通過的工作順序，不以原季度日期承諾新增功能上線。

| 順序 | 交付 | 進入／完成門檻 |
|---|---|---|
| 現在 | Founder 試用後，邀請約兩位已接觸供給方進行有協助的真實試用；補齊 P0 營運缺口 | 記錄真實操作、問題與測試範圍；交易 Email、備份復原、監控及 Beta 門檻另行驗收 |
| 下一個產品增量 P1 | 客戶關心工作台 RCH-001–007、009 | 教練確認名單與聯絡節奏；先範本／人工聯絡，驗證回約與打擾情況 |
| 下一個操作增量 P1 | 文字助手 ACT-001–005、007–009 | 建立服務草稿、查時段、準備自己的預約；重要條件釐清、預覽確認與權限／防撞案例通過 |
| 證據成立後 P2 | 語音 VOC-001–005、更多操作 ACT-006、010 | 文字流程可靠，再測辨識／校正、實體手機、成本與資料處理；保留文字表單 |
| 有渠道與偏好後 P2 | 自動關心 RCH-008 | 明確啟用、客戶同意、抑制與頻率、退訂、去重、預算及送信可靠性驗收 |

這些增量支援 SaaS 留存方向，不改變 Marketplace 後置與原生 App 後置。『語音操作任何事』是長期覆蓋方向，沒有一次開放所有操作的排程。規則、範本與既有 API 優先；生成式模型僅在可衡量地降低輸入負擔時加入。
