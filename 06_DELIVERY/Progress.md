## 2026-10-19 — Identity & Provider v0.2

已可在本機完成：Email 一次性連結 → 同瀏覽器確認 → 建立個人品牌 → 儲存服務草稿 → 編輯 → 發布／下架 → 查看公開頁 → 切換需求方／供給方模式。

驗證結果：52 項 Vitest（含失敗注入）、24 項桌面及模擬手機的瀏覽器／API 整合全部通過；TypeScript、文件與建置通過。實際包括六個同時驗證只成功一次、舊 Session 失效、停權拒絕、錯誤瀏覽器拒絕、寄信限流、跨租戶寫入拒絕、並發編輯只一筆成功、重複品牌網址回滾。已檢視登入、服務編輯、手機商業工作台與帳號設定截圖，瀏覽器無執行錯誤。

E2E 已改為每次獨立 D1、執行正式 build；測試啟動先確認本機驗證模式，避免真實寄信與混入開發資料。

限制：正式 Resend 寄送、品牌圖片、人工隱私案件處理尚未驗收。排班／可用時間、預約／申請／取消／改期、CRM、通知、ICS、管理後台與備份復原尚未完成。

## 2026-10-19 — Scheduling & Booking v0.3

已接通：供給方共用每週排班與日期例外 → 公開服務選時間 → 登入後保留所選時間 → 同意價格與政策 → 直接預約 → 雙方查看詳情／歷史 → 取消或提出改期 → 對方同意後原子換位。供給方可於結束後標記完成／未到場。

預約同批保存條件快照、客戶關係、唯一資源占用、冪等紀錄、事件、稽核與待送 Outbox。取消使用原快照期限；改期不修改原價格與政策。改期新配置或 Outbox 寫入失敗，整筆回滾並保留原安排。

驗證：68 項 Vitest、30 項桌面／模擬手機 Playwright、前端／Worker／工具型別、文件連結／173 條需求／OpenAPI 與正式 build 通過。兩個 Playwright 專案各執行本機 D1 100 請求競爭：一筆成功、99 筆衝突；供給方只有一筆預約，取消後時段恢復。同 key 八個並發重送回相同預約 id，不同內容重用回 409；同 key 四個並發取消均回成功。另包含 DST 春／秋、原取消截止、不同租戶拒絕、原子失敗注入、過期提案、舊版排班／服務拒絕、原條件保留及手機 320px 檢查。

已檢視桌面／手機預約詳情與排班畫面。測試使用獨立虛構資料，不寄信、不收款，並非正式雲端 D1 或實體手機壓力驗收。

剩餘：申請式預約及審核／到期、Outbox 消費與站內／Email 通知、ICS、CRM／手動安排、管理後台、正式部署／寄信、備份復原與獨立 Beta 審查。此版尚未完成所有 P0，不宣稱可正式營運。

下一工作包優先完成 Request to Book 與通知閉環，再補齊營運及 Beta 上線門檻。
