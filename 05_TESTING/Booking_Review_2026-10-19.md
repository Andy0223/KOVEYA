# 預約流程 review — 2026-10-19

觸發：Founder 在沒有可用時段的日期勾選同意後，滑鼠移至停用的送出按鈕時，看到等待游標。截圖並非正在送出請求，而是停用樣式誤用 `cursor: wait`。

範圍：公開服務／日期／選時段／申請送出、登入後保留選擇、失敗重試、手動預約、改期與替代時間的共用元件；並回歸既有帳號、租戶隔離、D1 防撞、CRM、通知與 ICS 測試。不是完整 PRD 或獨立安全稽核。

| 問題 | 修正 | 驗證 |
|---|---|---|
| 停用按鈕呈現無限等待游標，缺少停用原因 | 停用改為 not-allowed，實際送出才 aria-busy／wait；加入先選時段／同意條件提示 | 桌面／手機的 CSS、按鈕可操作性及真實待送狀態 |
| 前端請求無逾時，斷線可能一直等待 | 共用 API 15 秒 AbortController；提醒寫入可能成功，先查結果；不自動重送寫入 | 掛起請求、逾時、計時器釋放；已成功但回應遺失後同 key 重送只一筆申請 |
| URL 保留選擇時，未等待時段查詢完成即可準備送出；查詢錯誤未清理選擇 | 以目前查詢成功且包含該時段為送出條件；錯誤清除選擇，可重新查詢；改期／手動安排共用保護 | 查詢 503、重新查詢、清空日期、過期時段、登入保留與既有改期測試 |
| 異常 start 雖為 safe integer，仍超出 JavaScript Date 範圍而可能使畫面崩潰 | 驗證可表示的正時間點，移除無效參數 | 以 9007199254740991 開啟頁面仍可操作 |
| 免費服務仍要求直接付款 | 金額為 0 顯示無須付款 | 免費／收費文案及原有預約流程 |
| 資料庫或其他服務不可用被誤報為寄信未設定 | SERVICE_UNAVAILABLE 改為一般服務暫不可用；寄信失敗維持獨立錯誤 | 錯誤訊息測試 |

預約在後端仍須最終檢查時間、政策、租戶與資源；前端驗證不代表占位。15 秒停止等待不取消已提交至伺服器的交易。已有冪等鍵用於同一內容重試，沒有改成自動建立新操作。
